# Maintain generated documentation

Read the repository [agent guide](../../../AGENTS.md) first.

## Know the source and output boundary

- `bettermdptools/**/*.py`, especially module, class, and function docstrings, are
  source inputs for the pdoc API site.
- `README.md`, `docs/api/*.md`, and the redirect in `docs/index.html` are
  hand-authored source documentation. They are not generated by the pdoc command.
- Other committed HTML under `docs/` and `docs/search.js` are pdoc output.
- `pyproject.toml` pins pdoc in the optional Poetry `docs` group, and
  `poetry.lock` records the complete generator environment.

Edit source files first. Never manually patch pdoc-generated HTML or
`docs/search.js`. Do not broadly rewrite docstrings or prose in a narrow runtime
PR. Small source or docstring edits can cause very large generated diffs.

## Use the Poetry-managed generator

Install and run the pinned documentation tooling with:

```bash
poetry install --with docs
poetry run pdoc bettermdptools -o docs
```

Do not use an ambient pdoc executable or Python environment. Regenerate when an
intentional source docstring or public API change requires committed API pages to
be updated. The command owns generated API pages and `docs/search.js`, but it
does not own `docs/index.html` or `docs/api/`.

## Review intentional output

After regeneration:

1. Record the exact command and `poetry run pdoc --version`.
2. Separate source documentation changes from generated files in the change report.
3. Inspect the generated diff for removed pages, stale modules, duplicate trees,
   unrelated formatting churn, and source text that did not render as intended.
4. Run the same pdoc command a second time and confirm it produces no additional
   diff.
5. If the Poetry docs group cannot be installed, leave generated files unchanged
   and report documentation generation as unavailable.

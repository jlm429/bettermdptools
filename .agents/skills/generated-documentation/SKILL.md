# Maintain generated documentation

Read the repository [agent guide](../../../AGENTS.md) first.

## Know the source and output boundary

- `bettermdptools/**/*.py`, especially module, class, and function docstrings, are
  source inputs for the pdoc API site.
- `docs-templates/*.css` customizes the generated site.
- `README.md` and `docs/api/*.md` are hand-authored source documentation. They are
  not generated by the pdoc command.
- Committed `docs/**/*.html`, `docs/*.html`, `docs/index.html`, and `docs/search.js`
  are generated output. Their history and pdoc metadata show that this output is
  intentionally versioned.

Edit source files first. Never manually patch generated HTML or `docs/search.js`.
Do not broadly rewrite docstrings or prose in a narrow runtime PR. Small source or
docstring edits can cause very large, noisy generated diffs.

## Regenerate only when required

The discoverable repository command in `README.md` is:

```bash
pdoc --include-undocumented -d numpy -t docs-templates --output-dir docs bettermdptools
```

Regenerate only when an intentional source documentation or template change needs
the committed API pages updated. Do not regenerate for harness-only changes,
runtime changes with no documentation impact, or as a routine cleanliness check.
For validation without an intended docs update, generate into a temporary directory
instead of `docs/` when pdoc is already available.

The repository does not declare or pin pdoc in `pyproject.toml` or `poetry.lock`,
does not provide a generation script, and does not enforce generated-doc freshness
in checked-in CI. Existing committed pages identify both pdoc 15.0.0 and 16.0.0.
The command is established, but a byte-for-byte reproducible generator environment
is not. Do not add or change dependencies merely to regenerate docs unless the task
explicitly authorizes it.

## Review intentional output

After regeneration:

1. Record the exact command and `pdoc --version`.
2. Separate source documentation changes from generated files in the change report.
3. Inspect the generated diff for removed pages, stale modules, duplicate trees,
   unrelated formatting churn, and source text that did not render as intended.
4. If the generator is unavailable or version uncertainty makes the output unsafe,
   leave generated files unchanged and report that validation as unavailable.
